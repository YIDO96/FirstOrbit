# 조명(Lighting) 구현 가이드

> 3주차 로드맵 밖의 **보너스/스트레치 기능**이다. 이 문서는 "오늘 뭘 하나"가 아니라
> 단계별(Tier)로 구성했다 — 원하는 데까지만 하고 멈춰도 각 단계가 독립적으로 완성된 결과를 낸다.

---

## 0. 가장 먼저 알아야 할 것: 여기엔 "조명"이 없다

이 프로젝트는 **DirectX/OpenGL이 아니라 순수 Win32 GDI**로 그린다. GDI는:
- 셰이더가 없다 → 픽셀 단위 라이팅 모델(퐁, PBR 등) 자체가 존재하지 않는다
- 진짜 반투명(알파 블렌딩)이 기본 함수(`Rectangle`, `TextOutW`, `Ellipse`)엔 없다 — 색상키 투명(`TransparentBlt`)만 있다
- 그라디언트도 사각형/삼각형 선형 그라디언트(`GradientFill`)만 있고, **원형(radial) 그라디언트는 기본 제공 함수가 없다** — 직접 만들어야 한다

**그래서 여기서 "조명"은 전부 2D 합성 트릭이다:**
- "빛" = 중심이 밝고 가장자리가 투명해지는 스프라이트를 알파 블렌드로 겹쳐 그리는 것
- "그림자" = 어두운 반투명 스프라이트를 겹쳐 그리는 것
- 진짜 광원 방향에 따른 셰이딩이 아니라, **태양 방향만 계산해서 그 방향으로 어두운 오버레이를 씌우는 근사**

이 전제를 받아들이면 생각보다 GDI로도 꽤 그럴듯하게 나온다. 아래는 그 방법들이다.

### 지금 코드베이스에 이미 있는 재료 (확인 완료)
| 필요한 것 | 상태 |
|---|---|
| `msimg32.lib` (AlphaBlend/GradientFill 포함) | ✅ 이미 링크됨 (`pch.h`) — `TransparentBlt`도 여기서 옴 |
| DIB 직접 픽셀 접근 | ✅ `_hdcBack`엔 있음(`GameInstance::_backPixels`), ❌ `_hdcGame`(게임 월드 그리는 곳)엔 없음 — 필요하면 Tier 0.5에서 추가 |
| GDI+ | ❌ 안 씀. 이 가이드도 순수 Win32 GDI만 쓴다 |

## Tier 0.5 (선택) — `_hdcGame`을 DIB로 바꾸기

**언제 필요한가:** Tier 1(발광 스프라이트)은 `AlphaBlend()` HDC-to-HDC 블릿만으로 충분해서 이거 없이도 된다. **Tier 2(진짜 픽셀 단위 구체 셰이딩)까지 갈 때만 필요**하다. 지금 당장 안 해도 되고, 필요해지면 그때 와서 해도 된다.

`GameInstance.cpp::Init()`의 지금 코드:
```cpp
_hdcGame = CreateCompatibleDC(_hdc);
_bmpGame = CreateCompatibleBitmap(_hdc, GWinSizeX, GWinSizeY);   // ← DDB, 픽셀 접근 불가
SelectObject(_hdcGame, _bmpGame);
```
`_hdcBack`이 이미 쓰고 있는 패턴(`RecreateBackBuffer()`) 그대로 옮기면 된다:
```cpp
BITMAPINFO bi = {};
bi.bmiHeader.biSize = sizeof(BITMAPINFOHEADER);
bi.bmiHeader.biWidth = GWinSizeX;
bi.bmiHeader.biHeight = -GWinSizeY;   // top-down
bi.bmiHeader.biPlanes = 1;
bi.bmiHeader.biBitCount = 32;
bi.bmiHeader.biCompression = BI_RGB;

_bmpGame = CreateDIBSection(_hdc, &bi, DIB_RGB_COLORS, (void**)&_gamePixels, nullptr, 0);
SelectObject(_hdcGame, _bmpGame);
```
`GameInstance.h`에 `uint32_t* _gamePixels = nullptr;` 멤버와 `GetGamePixels()` 게터를 추가해두면 나중에 어디서든 쓸 수 있다.

## Tier 1 — 발광 스프라이트 (태양/별빛, 엔진 화염 글로우)

가장 결과 대비 노력이 적은 단계다. **한 번만 만들어서 캐싱해두고, 매 프레임은 그걸 위치·크기만 바꿔 블렌드**하는 구조로 간다.

### 1-1. 원형 그라디언트 텍스처를 직접 만들기 ⭐

GDI에 원형 그라디언트가 없으니, **한 번(로드 시점)만** 작은 DIB에 픽셀을 직접 써서 만든다. 이후엔 이 비트맵을 재사용만 한다 — 매 프레임 계산하면 안 된다.

```cpp
// 새 클래스: GameFramework/Glow.h/.cpp (또는 원하는 이름)
class Glow
{
public:
	void Create(int32 size);        // size x size 정사각형 글로우 텍스처 생성 (한 번만)
	void Render(HDC hdc, Vector2 centerPos, float radius, COLORREF color, BYTE intensity);

private:
	HBITMAP _bitmap = nullptr;
	HDC     _hdc = nullptr;
	int32   _size = 0;
};
```
```cpp
void Glow::Create(int32 size)
{
	_size = size;

	BITMAPINFO bi = {};
	bi.bmiHeader.biSize = sizeof(BITMAPINFOHEADER);
	bi.bmiHeader.biWidth = size;
	bi.bmiHeader.biHeight = -size;
	bi.bmiHeader.biPlanes = 1;
	bi.bmiHeader.biBitCount = 32;
	bi.bmiHeader.biCompression = BI_RGB;

	uint32_t* pixels = nullptr;
	HDC screenDC = ::GetDC(NULL);
	_bitmap = ::CreateDIBSection(screenDC, &bi, DIB_RGB_COLORS, (void**)&pixels, nullptr, 0);
	::ReleaseDC(NULL, screenDC);

	float center = size / 2.f;
	for (int32 y = 0; y < size; ++y)
	{
		for (int32 x = 0; x < size; ++x)
		{
			float dx = x - center;
			float dy = y - center;
			float dist = sqrtf(dx * dx + dy * dy) / center;   // 0(중심) ~ 1(가장자리)

			// ⭐ 판단할 것: 감쇠 곡선. 그냥 (1-dist)면 뭉툭하게 잘려 보인다.
			// 제곱을 쓰면 중심은 확 밝고 가장자리는 부드럽게 사라진다 (권장)
			float alpha = max(0.f, 1.f - dist);
			alpha = alpha * alpha;   // 제곱해서 더 부드럽게

			BYTE a = (BYTE)(alpha * 255);

			// AlphaBlend가 요구하는 "premultiplied alpha" 포맷: RGB에 알파를 미리 곱해둔다
			pixels[y * size + x] = (a << 24) | (a << 16) | (a << 8) | a;   // 흰색 premultiplied
		}
	}

	_hdc = ::CreateCompatibleDC(NULL);
	::SelectObject(_hdc, _bitmap);
}
```
> ⚠️ **AlphaBlend는 premultiplied alpha를 요구한다.** RGB 값에 알파를 미리 곱해두지 않으면 가장자리에 이상한 색 테두리(halo)가 생긴다. 위 코드는 흰색(255,255,255)에 알파를 곱한 값이라 `r=g=b=a`로 단순해졌다 — 색을 입히고 싶으면 `Render()`에서 곱셈 색상을 따로 적용하거나, 아예 컬러별로 다른 글로우 텍스처를 만들면 된다 (아래 판단할 것 참고).

```cpp
void Glow::Render(HDC hdc, Vector2 centerPos, float radius, COLORREF color, BYTE intensity)
{
	int32 destSize = (int32)(radius * 2.f);
	int32 x = (int32)(centerPos.x - radius);
	int32 y = (int32)(centerPos.y - radius);

	BLENDFUNCTION bf = {};
	bf.BlendOp = AC_SRC_OVER;
	bf.BlendFlags = 0;
	bf.SourceConstantAlpha = intensity;   // 전체 밝기(0~255) — 여기서 색 세기 조절
	bf.AlphaFormat = AC_SRC_ALPHA;        // 픽셀별 알파(위에서 만든 것) 사용

	::AlphaBlend(hdc, x, y, destSize, destSize, _hdc, 0, 0, _size, _size, bf);
}
```

**판단할 것:** 색상이 있는 빛(태양=노란빛, 블랙홀 강착원반=주황빛 등)을 표현하려면
1. 흰색 글로우 텍스처 하나만 만들고, `Render()` 호출 전에 `intensity`와 별개로 **원하는 색을 미리 곱한 새 텍스처를 색상별로 하나씩 캐싱**하거나
2. `AlphaBlend`는 자체적으로 색상 곱을 안 해주니, **텍스처 자체를 원하는 색으로 만들어둬야** 한다 (위 픽셀 채우는 루프에서 흰색 대신 원하는 RGB 사용)

지금 규모(태양 1개, 블랙홀 나오면 1개)면 색상별로 `Glow` 인스턴스를 하나씩 만들어 쓰는 게 제일 간단하다.

### 1-2. `MainWorld`에 태양 글로우 붙이기

`MainWorld.h`에 멤버 추가:
```cpp
Glow _sunGlow;
```
`MainWorld::Enter()`에서 한 번:
```cpp
_sunGlow.Create(256);   // 256x256 정도면 충분
```
`MainWorld::Render()` — **행성보다 먼저(뒤에) 그려야 태양 텍스처 위에 자연스럽게 겹친다**:
```cpp
void MainWorld::Render(HDC hdc)
{
	_starField->Render(hdc, _camera);

	// 태양 위치에 글로우 먼저 (행성/우주선보다 먼저 그려서 "배경 발광"처럼 보이게)
	Camera& cam = GetCamera();
	Vector2 sunScreenPos = cam.WorldToScreen(_sun->GetCenterPos());
	float glowRadius = cam.WorldToScreenScale(_sun->GetBodyRadius() * 3.f);   // 태양 반지름의 3배 정도 퍼짐
	_sunGlow.Render(hdc, sunScreenPos, glowRadius, RGB(255, 240, 180), 180);

	Super::Render(hdc);   // 행성/우주선 등 액터들
}
```
`_sun` 포인터가 지금 `MainWorld`에 따로 없으면(`InitPlanet()`에서 지역 변수로만 쓰고 있음) 멤버로 하나 승격해두면 된다.

### 1-3. 엔진 화염 글로우 (우주선)

같은 `Glow` 클래스를 재사용. `ASpaceship::Render()`에서 `_isThrusting`일 때만, 엔진 노즐 위치(우주선 뒤쪽, 로컬 좌표 기준 `Vector2(0, +10)` 정도)에 작은 주황 글로우를 얹는다:
```cpp
if (_isThrusting)
{
	Vector2 nozzleWorld = GetCenterPos() + GetForwardDir() * -10.f;   // 정면 반대 방향(뒤쪽)
	Vector2 nozzleScreen = cam.WorldToScreen(nozzleWorld);
	float r = cam.WorldToScreenScale(15.f);
	_engineGlow.Render(hdc, nozzleScreen, r, RGB(255, 140, 60), 200);
}
```
**판단할 것:** 화염을 고정 크기로 둘지, `sinf(시간)`으로 살짝 깜빡이게(pulsing) 만들지 — 후자가 훨씬 생동감 있다. `_trailSampleTimer`처럼 누적 시간 변수를 하나 더 두고 `radius *= 0.9f + 0.1f * sinf(elapsedTime * 20.f)` 식으로 흔들면 된다.

## Tier 2 — 태양 방향 그림자 (행성 명암)

행성이 태양 반대편은 어둡게 보이는 것. **진짜 구체 셰이딩(픽셀별 법선·내적 계산)은 안 하고, 근사로 간다.**

### 2-1. 근사 방법: 반원 오버레이 (권장, 가장 쉬움)
행성 중심에서 "태양 반대 방향"으로 오프셋한 어두운 반투명 원을 하나 더 그린다. 완전히 정확한 터미네이터 선은 아니지만, 화면상 5~30px 크기 행성에선 충분히 그럴듯하다.

```cpp
// APlanet::Render() — 텍스처 그린 다음
if (_ownerWorld의 태양 위치를 알 수 있다면)   // 판단할 것 아래 참고
{
	Vector2 dirFromSun = (GetCenterPos() - sunPos).Normalized();
	Vector2 shadowCenter = screenPos + dirFromSun * (r * 0.6f);   // 태양 반대쪽으로 살짝 오프셋

	// _shadowGlow: 검은색으로 만든 Glow 인스턴스 (Tier 1의 Glow 클래스 재사용)
	_shadowGlow.Render(hdc, shadowCenter, r * 0.9f, RGB(0, 0, 0), 140);
}
```
`AlphaBlend`가 텍스처 위에 검은 반투명 원을 자연스럽게 섞어주므로, 결과적으로 "태양 반대쪽이 어두운" 것처럼 보인다.

**판단할 것 — 태양 위치를 행성이 어떻게 알까:**
1. `APlanet`에 `static APlanet* s_sun` 같은 정적 포인터를 두고 `MainWorld::InitPlanet()`에서 태양 생성 시 등록 (간단하지만 전역 상태라 결합도 높음)
2. `APlanet::Render(HDC hdc, Vector2 sunPos)` 처럼 `Render()` 시그니처에 태양 위치를 인자로 추가 (깨끗하지만 `AActor::Render(HDC)` 베이스 시그니처와 안 맞아서 오버라이드 체계가 깨짐)
3. `APlanet`에 `bool _isLightSource` 플래그를 하나 두고, `MainWorld::Render()`가 행성들을 순회하며 태양 위치를 직접 찾아 각 `APlanet`에 `SetLightDir(...)`을 매 프레임 호출 (가장 이 프로젝트 패턴과 잘 맞음 — 이미 `SetTexture()`처럼 "월드가 액터에게 필요한 정보를 넣어준다"는 방식을 쓰고 있음)

3번을 추천한다 — `AActor::Render(HDC)` 시그니처를 안 건드리고, 전역 정적 상태도 안 만든다.

### 2-2. 더 정확하게 가고 싶다면 (픽셀 단위, 상당히 무거움)
행성을 그릴 때 텍스처의 각 픽셀마다 "이 픽셀의 구체 표면 법선"과 "태양 방향"의 내적을 계산해서 밝기를 조절하는 진짜 구체 셰이딩. 이건 `_hdcGame`을 DIB로 바꾼(Tier 0.5) 다음, 텍스처를 직접 순회하며 픽셀을 다시 써야 해서 **매 프레임 비용이 꽤 크다** (행성 텍스처 크기 × 행성 개수). 화면상 행성이 30px 안팎인 이 게임 스케일에선 2-1(근사)과 시각적 차이가 크지 않을 가능성이 높다 — **권장하지 않음.** 정 해보고 싶다면 별도로 문의.

## Tier 3 — 블랙홀 (시각 요소로 한정)

> 📌 **먼저 확실히 할 것 — 판단할 것:** "블랙홀"이 **순수 배경 장식(시각 효과만)**인지, 아니면 **실제로 중력을 미치는 새 천체(물리 오브젝트)**인지에 따라 작업이 완전히 갈린다. 이 가이드는 **시각 효과만** 다룬다. 실제 중력원으로 넣고 싶다면 이건 "조명"이 아니라 `APlanet`을 하나 더 만드는 물리 작업이라 — 그건 원하시면 별도로 가이드 드릴게요.

시각적으로 블랙홀은 두 겹이면 충분히 그럴듯하다:
1. **강착원반 글로우** — Tier 1의 `Glow`를 주황/보라색으로, 크게 (`radius`를 이벤트 호라이즌보다 훨씬 크게)
2. **이벤트 호라이즌(사건의 지평선)** — 글로우 위에 **완전히 불투명한 검은 원**을 덮어 그림 (그냥 `Ellipse` + `CreateSolidBrush(RGB(0,0,0))`, 알파 필요 없음 — 빛을 "전부 가리는" 거니까 오히려 불투명이 맞다)

```cpp
void ABlackHole::Render(HDC hdc)
{
	Camera& cam = _ownerWorld->GetCamera();
	Vector2 screenPos = cam.WorldToScreen(GetCenterPos());
	float horizonR = cam.WorldToScreenScale(_bodyRadius);

	_accretionGlow.Render(hdc, screenPos, horizonR * 4.f, RGB(255, 140, 40), 220);   // 강착원반(바깥, 먼저)

	HBRUSH brush = ::CreateSolidBrush(RGB(0, 0, 0));                                 // 사건의 지평선(안쪽, 나중에 = 위에 덮임)
	HBRUSH old = (HBRUSH)::SelectObject(hdc, brush);
	::Ellipse(hdc, (int)(screenPos.x - horizonR), (int)(screenPos.y - horizonR),
	               (int)(screenPos.x + horizonR), (int)(screenPos.y + horizonR));
	::SelectObject(hdc, old);
	::DeleteObject(brush);
}
```
**그리는 순서가 핵심이다.** 글로우(넓고 흐림) → 검은 원(좁고 불투명) 순서로 그려야 "가운데는 새까맣고 가장자리만 빛난다"는 느낌이 난다. 반대로 하면 검은 원이 글로우에 덮여서 안 보인다.

> 💡 **중력 렌즈 효과(배경 별빛이 블랙홀 주변에서 휘어 보이는 것)는 이 가이드에서 제외한다.** 실시간으로 하려면 배경을 별도 텍스처로 렌더링한 뒤 픽셀 단위로 왜곡시켜야 하는데, 이건 셰이더 없이 GDI만으론 프레임마다 감당하기 어렵다. n-body를 스코프에서 뺀 것과 같은 이유 — "안 되는 게 아니라 이 프로젝트 규모에서 비용 대비 효과가 안 맞는다."

## 4. 성능 체크리스트 (전부 공통)

- [ ] `Glow::Create()`(픽셀 채우는 루프)는 **로드 시점에 한 번만** 부른다 — `Render()`나 `Update()` 안에서 매 프레임 부르면 안 된다
- [ ] `AlphaBlend` 호출 자체는 영역(픽셀 수)에 비례해서 비용이 든다 — 글로우 텍스처를 256x256 이상으로 키우지 말고, 화면에 그릴 때 `destSize`(스케일)로 크기를 조절할 것
- [ ] 이 프로젝트는 Debug 빌드가 유독 느리다(17번 트러블슈팅 항목 참고) — **성능은 항상 Release로 측정**할 것
- [ ] 별(`StarField`)이 20000개 단위라, 여기에 글로우까지 겹치는 실수는 하지 말 것 (글로우는 태양·블랙홀처럼 **개수가 적은 대상**에만)

## 5. 추천 진행 순서

1. **Tier 1 (발광 스프라이트)** — 결과가 가장 빨리, 확실하게 보인다. 태양부터.
2. **Tier 1의 엔진 화염** — 같은 `Glow` 클래스 재사용이라 거의 공짜.
3. **Tier 3 (블랙홀, 시각만)** — Tier 1 클래스를 그대로 재사용, 검은 원 하나만 추가.
4. **Tier 2 (그림자, 근사)** — 판단할 것(태양 위치 전달 방식)이 있어서 살짝 더 걸림.
5. Tier 2의 픽셀 단위 정밀 셰이딩, 중력 렌즈 — **권장하지 않음** (비용 대비 효과 낮음, 이 문서에서도 의도적으로 얕게만 다룸).
