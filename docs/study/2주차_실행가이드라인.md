## 1. 시작 파라미터 ⭐

> 1주차에서 정한 값(행성 반지름 1000, 대기권 300)에서 **역산으로 유도한 값들**이다.
> 유도 과정은 학습가이드 A-4. 그대로 넣고 시작한 뒤 직접 만져가며 조정할 것.

### 중력 단위계

| 항목 | 값 | 근거 |
|---|---|---|
| 행성 반지름 `R` | **1000** | 1주차에서 결정 |
| 표면 중력 `g` | **20 units/s²** | 1초 낙하 = 10 units ≈ 우주선 크기. 눈에 보이면서 안 빠름 |
| **중력 파라미터 `μ`** | **2.0 × 10⁷** | `μ = g·R² = 20 × 1000²` |

> 📌 **`μ` 하나만 저장한다.** `G`와 `M`을 따로 두지 않는다 (학습가이드 A-2).

### 여기서 파생되는 값 — 미리 계산해둘 것

디버깅 중에 "지금 이 숫자가 말이 되는가"를 즉시 판단하려면 이 표가 필요하다.

| 양 | 공식 | 값 |
|---|---|---|
| 원궤도 속도 (고도 300, `r`=1300) | `√(μ/r)` | **`≈ 124`** |
| 탈출 속도 (지표면, `r`=1000) | `√(2μ/R)` | **`200`** |
| 궤도 주기 (`r`=1300) | `2πr/v` | **`≈ 66초`** |
| 원궤도 에너지 (`r`=1300) | `½v² - μ/r` | `≈ -7690` |

### 우주선 / 추력

| 항목 | 시작값 | 근거 |
|---|---|---|
| 우주선 질량 `m` | **1.0** | `F = a`가 되어 추력을 가속도로 직접 다룰 수 있다 |
| 추력 가속도 | **35 units/s²** | TWR = 35/20 = **1.75** (실제 로켓 이륙 시점 범위) |
| 회전 속도 | **90 deg/s** | 기존 `ASpaceship::_rotSpeed` 유지 |
| 카운트다운 | **3초** | 로드맵 "3·2·1" |

> 💡 **TWR(추력대중량비) = 추력가속도 / 표면중력.** `TWR < 1`이면 이륙 자체가
> 불가능하다. **일부러 `TWR = 0.9`로 두고 안 뜨는지 확인**하는 게 물리가 맞다는
> 가장 강력한 증거다 (Day 5 검증).

### 적분 / 타임스텝

| 항목 | 시작값 | 근거 |
|---|---|---|
| `FIXED_DT` | **1/120 s** | 궤도는 오차가 누적되는 계라 60Hz보다 안전 |
| `MAX_STEPS` | **5** | 죽음의 나선 방지 (학습가이드 A-6) |
| 기본 적분기 | **반암시적 오일러** | 안정성. 나머지는 비교용 |

### 📌 전부 ImGui 슬라이더로 빼둘 것

1주차와 같은 원칙이다. 2주차는 **튜닝할 값이 훨씬 많아서** 이게 더 중요하다.
`μ`, 추력, `FIXED_DT`, 적분기 선택을 전부 런타임에 바꿀 수 있게 해두면
Day 7의 튜닝이 몇 시간 단축된다.

이 프로젝트는 발사와 궤도가 **다른 월드**에서 진행된다.

| | LaunchWorld | MainWorld |
|---|---|---|
| 무대 | 평면 지면 (월드 `y = 0`) | 태양계 (행성 9개) |
| 중력 | **균일 중력** `(0, +20)` | **행성 중력** `μ·d/r³` |
| 고도 | `-y` | `r - bodyRadius` |
| 여기서 하는 것 | 발사·추력·조작감 | **궤도·적분기 검증** |

> 행성 중력 위에서만 성립하는 실험이라 평면 월드에서는 할 수 없다.
> **`UPhysicsComponent`는 한 벌로 두고, `ComputeAcceleration`이 "월드에 행성이
> 있으면 행성 중력, 없으면 균일 중력"으로 갈라지게** 하면 코드가 두 벌이 되지 않는다.

> 🔒 **Day 3과 Day 7이 이번 주차의 핵심이다.** Day 3(원궤도)이 안 되면 그 뒤가
> 전부 무의미하고, Day 7(비교 하네스)이 포트폴리오 산출물이다.
> **밀리면 Day 5~6을 줄이고 이 둘을 사수한다.**

# Day 1 — 단위계 + 물리 컴포넌트 골격

> **목표:** 물리 상태를 가진 컴포넌트가 붙고, 가속도 함수의 껍데기가 선다.
> 개념 학습은 적다. **설계 판단을 내리는 날이다.**
> **📖 시작 전 읽기:** 학습가이드 A-1, A-2, A-4

### 체크리스트

- [ ] **1-1. 단위계 상수 정의** `~15분`

  - **판단할 것:** `APlanet`에 `_mu`를 두는 걸 권한다 (학습가이드 A-2).

- [ ] **1-2. `UPhysicsComponent` 생성** `~30분`

- [ ] **1-3. 물리 상태 멤버** — `B-1` `~20분`

- [ ] **1-4. `ComputeAcceleration` 시그니처** — `B-1` ⭐ `~20분`

  ```cpp
  // RK4가 중간 지점을 평가해야 하므로 반드시 이 형태여야 한다 (학습가이드 A-5-8)
  ```

- [ ] **1-5. `ASpaceship`에 컴포넌트 부착 + 임시 적분** `~30분`

  - ⚠️ `ASpaceship::_gravity = 9.8f` 멤버는 **지운다** (중력은 이제 물리 쪽 담당)

# Day 2 — 추력 전환 + 중력

> **목표:** 추력이 힘이 되어 중력과 겨룰 수 있게 되고, 만유인력이 들어간다.
> **📖 시작 전 읽기:** 학습가이드 A-2, A-3, B-5, Part C-1

### 체크리스트 — `B-5` 추력 전환 (LaunchWorld) ⭐

> 원래 Day 5 항목인데 앞으로 당겼다. **이걸 먼저 하지 않으면 중력을 넣는 순간
> 우주선이 반드시 떨어지고, 값을 아무리 키워도 해결되지 않는다.**

- [ ] **⭐ 2-1. 추력을 위치 이동에서 가속도로** `~40분`
  ```
  현재:  _pos += _forwardDir * _moveSpeed * dt     ← 속도 차원 (일정)
  변경:  a_thrust = _forwardDir * (thrust / mass)  ← 가속도 차원 (누적)
  ```
  - **왜 값 조정으로는 안 되는가:** 추력이 속도(`units/s`)고 중력이
    가속도(`units/s²`)면 **차원이 달라 겨룸이 성립하지 않는다.** 중력만
    누적되므로 `_moveSpeed`를 10배로 올려도 이기는 시간이 10배 늘 뿐이다
  - `ASpaceship::_moveSpeed`(속도)를 `_thrust`(가속도)로 교체
  - **판단할 것:** 추력을 `ComputeAcceleration` 안에 넣을지, 밖에서 더할지
    → 안에 넣으면 Day 4의 RK4가 추력까지 4차로 처리한다. 밖은 순수성이 유지된다.
      **정답이 없으니 정하고 이유를 주석으로 남길 것**

- [ ] **2-2. TWR로 값 잡기** `~20분`
  ```
  TWR = 추력가속도 / 중력가속도
  TWR < 1      이륙 불가
  TWR 1.5~2    실제 로켓 이륙 시점 — 묵직하게 뜬다   ← 권장
  TWR 3~4      너무 가벼워서 조작이 시시해진다
  ```
  - `g = 20`이므로 **추력 `35`(TWR 1.75)** 로 시작
  - 체감: 5초 붙잡으면 상승속도 75·고도 190, 손 떼면 최고 고도 약 330

- [ ] **⭐ 2-3. 관성 확인** `~15분`
  - `W`를 떼도 **계속 나아가는가** (즉시 멈추면 아직 위치를 직접 옮기는 중)
  - 추력 없이 두면 떨어지는가

- [ ] **2-4. TWR < 1 검증** `~15분`
  - 추력을 `18`(TWR 0.9)로 낮추면 **이륙하지 못하는가**
  - **물리가 맞다는 가장 강력한 증거다.** 확인 후 `35`로 되돌린다

- [ ] **2-5. 위치 쓰기 경로 정리** `~10분`
  - ⚠️ `_pos +=`(입력)와 `SetCenterPos`(물리)가 **같은 프레임에 위치를 두 번 쓰던**
    상태를 해소한다. 이제 위치를 쓰는 곳은 `UPhysicsComponent` 하나여야 한다

### 체크리스트 — `B-2` 중력 (MainWorld 준비)

- [ ] **2-6. 단일 행성 중력** `~40분`
  ```
  d  = 행성중심 - 우주선위치        ← ⚠️ 순서. 뒤집으면 척력이 된다
  r2 = d.LengthSquared()
  r  = sqrt(r2)
  a += d * (mu / (r2 * r))          ← r³ 한 번에 (학습가이드 A-3)
  ```
  - ⚠️ `Normalized()`를 부르지 말 것. `r³`으로 나누면 정규화가 포함된다

- [ ] **2-7. `r → 0` 클램프** `~10분`
  - `r = max(r, bodyRadius)` — 행성 내부는 게임상 의미가 없다
  - 안 하면 `NaN`이 전염되어 우주선이 화면에서 사라진다

- [ ] **2-8. 월드에 따라 중력원 가르기** `~20분`
  - LaunchWorld는 행성이 없으므로 **균일 중력 `(0, +20)`**
  - MainWorld는 **행성 순회 합산**
  - ⚠️ **`UPhysicsComponent`를 두 벌로 만들지 말 것.** `ComputeAcceleration`
    안에서 "행성이 있으면 행성 중력, 없으면 균일 중력"으로 갈라지게 한다

- [ ] **⭐ 2-9. 방향 부호 검증 (4방향)** `~30분`
  - MainWorld에서 우주선을 행성의 **위 / 아래 / 왼쪽 / 오른쪽**에 각각 놓고 속도 0
  - **매번 행성 쪽으로 떨어지는가**
  - ⚠️ **한 방향만 테스트하면 부호 실수를 못 잡는다.** 1주차 표면 정렬(A-8)에서
    겪은 것과 정확히 같은 함정이다

- [ ] **2-10. 자유낙하 해석해 대조 (LaunchWorld)** `~40분`
  - 균일 중력 `g = 20`인 LaunchWorld가 그대로 이 검증 무대다
  - 1초 후 속도 `≈ 20`, 낙하 거리 `≈ 10`, 2초 후 `≈ 40`
  - ⚠️ **정확히 안 맞는 게 정상이다.** 반암시적 오일러는 `½gt²`에서 약간 벗어난다.
    **`dt`를 줄였을 때 값이 수렴하는지**를 보면 된다

- [ ] **⭐ 3-0. MainWorld에 우주선 스폰** `~20분`

  ```
  x += v · dt          ← 새 v를 사용
  ```

  ```
  방향 = 반지름에 수직 →  d̂ = (우주선-행성).Normalized()
  ```

# Day 4 — 명시적 + RK4 + 고정 타임스텝 📸

> **목표:** 적분기 3종이 런타임에 교체되고, 물리가 프레임률과 무관해진다.
> **📖 시작 전 읽기:** 학습가이드 A-5-6~A-5-8, A-6

### 체크리스트 — `B-3` (3-2, 3-3)

- [ ] **4-1. 적분기 enum + 런타임 전환** `~20분`
  ```cpp
  enum class EIntegrator { SemiImplicitEuler, ExplicitEuler, RK4 };
  ```
  - ImGui 콤보박스로 전환

- [ ] **📸 4-2. 명시적 오일러** `~30분`
  ```
  a = ComputeAcceleration(x, v)     ← ⚠️ x를 갱신하기 전에 미리 구해둔다
  x += v · dt                        ← 옛 v를 사용
  v += a · dt
  ```
  - ⚠️ **위치를 먼저 갱신하고 가속도를 구하면 의도치 않게 반암시적이 된다.**
    차이가 안 나면 실험이 무의미하다
  - **검증:** 원궤도 초기 조건에서 **바깥으로 나선**을 그리는가
    (안쪽으로 말리면 부호나 순서가 반대다)
  - **⭐ 스크린샷을 남길 것** — 우주선이 나선을 그리며 날아가는 장면

- [ ] **4-3. RK4** `~60분`
  ```
  k1 = f(y)
  k2 = f(y + (dt/2)·k1)
  k3 = f(y + (dt/2)·k2)
  k4 = f(y + dt·k3)
  y += (dt/6)·(k1 + 2k2 + 2k3 + k4)
  ```
  - **판단할 것:** 상태 `(pos, vel)` / 미분 `(dPos, dVel)` 구조체를 만들지
    → 만드는 걸 권한다. 없으면 변수 8개로 코드가 뒤덮인다
  - ⚠️ 가중치 `1:2:2:1`, 나누는 값 `6`
  - ⚠️ `k2`/`k3`는 `dt/2`, `k4`는 `dt` 전체
  - ⚠️ `f(y)`가 반환하는 건 `(속도, 가속도)`다 — 위치의 변화율이 속도,
    속도의 변화율이 가속도

- [ ] **4-4. RK4 차수 검증** ⭐ `~30분`
  - `dt`를 절반으로 줄이면 궤도 오차가 **약 1/16**이 되는가
  - **이게 확인되면 RK4 구현이 진짜 맞은 것이다** (4차 정확도)

### 체크리스트 — `B-4` 고정 타임스텝

- [ ] **4-5. 누산기 패턴** `~40분`
  ```
  _accumulator += frameTime;
  int steps = 0;
  while (_accumulator >= FIXED_DT && steps < MAX_STEPS)
  {
      PhysicsStep(FIXED_DT);
      _accumulator -= FIXED_DT;
      ++steps;
  }
  if (steps >= MAX_STEPS) _accumulator = 0.f;   // 밀린 시간은 버린다
  ```
  - ⚠️ **`MAX_STEPS`를 빼먹으면 죽음의 나선.** 디버거로 멈췄다 재개하면 재현된다

- [ ] **4-6. 프레임률 독립성 확인** `~20분`
  - 무거운 연산을 일부러 넣어 프레임을 떨어뜨려도 같은 조작 → 같은 결과
  - 디버거로 5초 멈췄다 재개해도 프리즈 없이 이어지는가

### ✅ Day 4 끝 판정
> 세 적분기가 런타임에 교체되고, 명시적은 발산 · RK4는 가장 정확하다.

## 4. 막혔을 때 — 범위 좁히기

물리는 **"언제부터 틀렸는지"** 를 좁히는 게 전부다. 순서대로 되돌려본다.

```
0. 차원이 맞는가?                        → 속도와 가속도를 겨루게 해두지 않았는가
1. 중력을 상수(g=20)로 바꾸면 되는가?   → 되면 중력 계산 문제 (부호·r³·클램프)
2. 적분기를 반암시적으로 바꾸면?         → 되면 명시적/RK4 구현 문제
3. dt를 10배 줄이면 되는가?              → 되면 적분 오차 (알고리즘은 맞음)
4. 추력을 끄면 되는가?                   → 되면 추력 계산 / 중력 이중 적용
5. 행성을 하나만 남기면?                 → 되면 다중 행성 합산 문제
6. 자유낙하 해석해와 대조                → 여기서도 틀리면 가장 기본이 문제
```

> 🔑 **0번을 맨 앞에 둔 이유:** "값을 얼마로 하면 되나?"라는 질문이 나왔을 때
> 그게 사실 **차원 문제**인 경우가 아주 많다. 차원이 어긋나 있으면 어떤 값을
> 넣어도 시간이 지나면 결과가 뒤집히므로, **튜닝으로 해결하려다 몇 시간을 태운다.**
> 의심 순서는 항상 **차원 → 부호 → 크기**다.

> 💡 **1~2번을 먼저 하는 게 핵심이다.** 중력과 적분기 중 어느 쪽인지만 갈라도
> 탐색 범위가 절반이 된다.
>
> ⚠️ **물리 버그는 원인이 하나가 아닐 때가 많다.** "하나씩 정상으로 되돌리며
> 좁히는" 접근이 유일하게 통한다. 여러 개를 동시에 고치려 들면 더 헤맨다.
